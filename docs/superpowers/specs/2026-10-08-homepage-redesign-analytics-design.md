## 3. 제작 도구와 결과물

### Lovable: 시각 초안

연결된 사장님 워크스페이스에서 전남열쇠 고객 홈페이지의 데스크톱·모바일 초안을 만든다. 초안에는 공개 업체 정보와 승인된 가격·문구만 전달한다. 고객 문의 기록, 사진, 운영 비밀값은 전달하지 않는다.

초안의 목적은 화면 구성과 시각 디자인 결정이다. 운영 데이터베이스를 새로 만들거나 기존 사이트의 주소·호스팅을 옮기지 않는다. 별도 운영 사이트를 공개하지 않는다. Lovable 결과의 문구와 기능은 기존 요구사항에 맞는지 확인한 뒤 사용한다.

### Figma: 관리 가능한 디자인 원본

홈페이지 데스크톱·모바일 화면과 관리자 통계 화면을 편집 가능한 프레임으로 정리한다. 색상, 글자 크기, 여백, 버튼·가격표·입력창·통계 카드의 공통 규칙을 함께 기록한다. 단일 스크린샷만 붙여 넣은 파일로 대체하지 않는다.

Lovable와 Figma 계정 연결은 확인했다. 아직 이 작업의 외부 프로젝트나 Figma 파일은 생성하지 않았다. 현재 Figma 계정의 파일 생성·편집 가능 여부는 해당 단계에서 확인한다. 권한 또는 요금제 제한이 확인되면 제한 사항과 가능한 대안을 알리고, 유료 전환이나 도구 생략을 임의로 결정하지 않는다.

### Superpowers: 구현과 검증

검토된 설계와 구현 계획을 기준으로 기존 코드에 디자인과 통계를 적용한다. 통계 계산·접근 권한·기존 접수 흐름을 검증하고 같은 운영 사이트에 배포한다. 최종 결과물은 운영 URL, Lovable 초안, Figma 디자인 원본, 검증 결과다.

## 4. 고객 홈페이지 디자인

### 시각 방향

밝은 아이보리 바탕과 짙은 네이비 글자·버튼을 사용한다. 충분한 여백과 큰 한글 제목, 읽기 쉬운 숫자로 가격과 상담 행동을 강조한다. 모바일에서는 한 열로 자연스럽게 이어지고, 전화 상담과 사진 견적 버튼에 쉽게 접근할 수 있게 한다. 과도한 애니메이션은 사용하지 않는다.

### 화면 구성

1. **상단:** 전남열쇠 이름, 가격표·사진 견적·후기·매장 안내 이동.
2. **첫 화면:** 광주 도어락 설치·교체 안내, 전화 상담과 사진 견적 버튼, 도어락 이미지.
3. **지정 제품 가격표:** 아래 가격과 적용 조건을 한눈에 볼 수 있는 구성.
4. **별도 사진 견적:** 설치 정보 → 문·제품 사진 → 성함·전화번호·주소 입력의 기존 접수 흐름.
5. **후기와 서비스 안내:** 출처가 확인된 기존 내용과 네이버 후기 링크. 허구의 후기·별점·시공 건수를 만들지 않는다.
6. **매장 안내:** 기존 확인된 영업 정보, 전화, 주소, 네이버 지도 링크.
7. **하단:** 개인정보 안내와 사장님 관리 진입. 모바일 상담 버튼이 입력 내용이나 제출 버튼을 가리지 않게 한다.

| 지정 제품 종류 | 설치비 포함 가격 |
| --- | ---: |
| 현관정 | 60,000원 |
| 보조키 도어락 | 120,000원 |
| 손잡이형 주키 도어락 | 150,000원 |
| 푸시풀 도어락 | 220,000원 |
| 푸시풀 지문 도어락 | 250,000원 |

가격표는 **정해진 제품에만 적용**된다. 해당 제품의 타공 작업이 필요하면 **10,000원 추가**다. 원하는 다른 모델은 사진과 현장 조건을 확인한 뒤 별도 견적을 안내한다. 문의 양식에서 위 금액을 자동 확정하거나 결제 금액으로 제시하지 않는다.

기존 도어락 연출 이미지를 사용할 경우 실제 시공 사진으로 표현하지 않는다. 새 시각 자료도 같은 원칙을 따른다.

## 5. 관리자 방문 통계 화면

기존 견적 접수함과 무료 알림 설정 옆에 **방문 통계** 탭을 추가한다. `/admin#analytics`로 직접 열 수 있게 하고, 사장님 계정 인증을 통과한 뒤 데이터에 접근한다.

- 기본 조회 날짜: **오늘, 한국 시간(Asia/Seoul)**.
- 날짜 선택과 이전 날짜 이동: 수집 시작일부터 최근 90일 이내. 미래 날짜 선택 금지.
- 요약 카드: 선택한 날짜의 **방문자(브라우저 기준)**, **페이지 조회 수**.
- 그래프: 0시부터 23시까지 24개 구간. 방문자·조회 수를 구분해서 표시한다.
- 그래프와 같은 숫자를 읽을 수 있는 시간별 표를 제공한다. 색상만으로 지표를 구분하지 않는다.
- 새로고침 버튼과 마지막 집계 시각을 제공한다. 화면을 계속 열어두는 자동 갱신은 이번 범위에서 제외한다.
- 0건, 수집 시작 전, 보관 기간 밖, 로딩, 조회 실패 상태를 서로 구분한다. 실패를 0명으로 표시하지 않는다.
- 오늘의 아직 오지 않은 시간은 미집계 구간임을 표시한다.

통계 탭의 오류는 견적 접수함이나 알림 설정을 사용할 수 없게 만들지 않는다.

## 6. 집계 기준과 한계

**방문자**는 실제 사람을 식별한 숫자가 아니라, 당일에 발급한 익명 식별자로 중복을 줄인 브라우저 수다. 다른 기기·브라우저, 비공개 모드, 저장 정보 삭제에 따라 같은 사람이 여러 방문자로 집계될 수 있다.

- **일 방문자:** 선택한 한국 날짜에 한 번 이상 조회한 익명 브라우저의 중복 제거 수.
- **시간별 방문자:** 해당 시간에 한 번 이상 조회한 익명 브라우저의 중복 제거 수.
- **페이지 조회:** 공개 홈페이지 문서가 사용자에게 표시된 횟수. 새로고침과 뒤로가기·앞으로가기를 통한 재표시는 새 조회로 처리한다.
- 한 브라우저가 10시와 11시에 모두 방문하면 각 시간에는 1명씩, 하루 합계에는 1명이다. 따라서 시간별 방문자 합계를 일 방문자로 사용하지 않는다.
- 같은 페이지 안에서 가격표·견적 영역으로 이동하거나 폼 단계를 바꾸는 것은 새 조회가 아니다.
- 관리자, API, 이미지·스크립트 파일 요청은 방문 통계에 포함하지 않는다. 로그인 상태로 식별되는 사장님의 홈페이지 조회도 제외한다. 로그아웃 상태의 사장님은 일반 방문자와 구분할 수 없다.
- 네트워크 재시도는 같은 이벤트 ID를 사용해 조회 수가 중복 증가하지 않게 한다.
- 날짜·시간은 브라우저 시계 대신 서버 수신 시각을 한국 시간으로 변환해 결정한다. 장시간 지연된 전송은 서버에 도착한 시간에 속한다.
- 명백한 검색 봇·자동 요청은 필터링하지만 모든 봇을 완벽하게 제거한다고 표시하지 않는다. 추적 차단이나 전송 실패로 일부 조회가 누락될 수 있다.
- **적용 시점 이후부터 수집**한다. 수집 전의 과거 방문 통계는 복원하거나 임의 생성하지 않는다.

광고 노출 수나 네이버 광고 클릭 수와는 다른 지표다. 이번 기능은 실제 홈페이지에 도착하여 표시된 방문을 집계하며, 광고 플랫폼 수치를 대신하지 않는다.

## 7. 수집·저장·조회 구조

### 수집

공개 홈페이지에 작은 독립 스크립트를 추가한다. 문서가 화면에 표시됐을 때 동일 출처 수집 API로 이벤트 ID를 전송한다. 숨겨진 탭에서 미리 열린 문서는 처음 표시될 때 처리한다. 고객 입력값이나 사진에는 접근하지 않는다.

수집 API는 당일에만 유효한 서버 서명 익명 쿠키를 사용한다. 쿠키는 자사 사이트 전용이며 Secure·HttpOnly·SameSite 속성을 사용하고 한국 시간 자정에 만료한다. 원장에는 당일 식별자의 해시를 기록해 날짜를 넘는 개인별 행동 이력을 만들지 않는다.

요청 본문 크기, 이벤트 ID 형식, 동일 출처, 관리자 여부, 명백한 봇을 검사한다. 기존 비밀값에서 용도를 구분해 서명·요청 제한 키를 파생하고 비밀값을 브라우저로 보내지 않는다. 해시 기반의 짧은 요청 제한으로 반복 전송을 억제하고 원시 IP는 통계에 저장하지 않는다. 식별 쿠키를 사용할 수 없으면 방문자 추정치가 부풀 수 있음을 안내한다.

통계 전송은 견적 기능과 독립적으로 처리한다. 통계 API 오류·쿠키 차단·스크립트 실패가 가격표 열람, 사진 첨부, 문의 제출을 막아서는 안 된다.

### 저장

D1에 분석용 이벤트 테이블과 필요한 인덱스·정리 상태를 **추가 마이그레이션**으로 만든다. 이벤트 ID에 유일 제약을 두고, 한국 날짜·시간과 익명 브라우저 키로 조회 수 및 중복 제거 수를 계산한다. 이벤트 중복 방지와 집계가 원자적으로 일어나게 한다.

최근 90일을 조회 범위로 삼는다. 다음 수집 또는 관리자 통계 조회 시 하루 한 번 오래된 통계 원장을 정리한다. 트래픽이 없는 동안에는 다음 요청 때 정리되므로 정각 삭제를 약속하지 않는다. 기존 견적·사진·푸시 테이블의 데이터와 마이그레이션 이력을 수정하거나 초기화하지 않는다.

고객 이름·전화번호·주소·사진, 원시 IP, 전체 User-Agent, URL 쿼리 문자열을 통계 원장에 저장하지 않는다. 고객 문의와 방문 식별자를 결합하지 않는다. 개인정보 안내에는 익명 방문 집계의 목적·항목·유효기간·한계를 실제 구현과 일치하게 추가한다.

### 조회

관리자 통계 API는 기존 `requireAdmin` 권한 검사를 사용한다. 요청 날짜를 검증하고 항상 24시간 배열과 일 합계, 집계 시각을 반환한다. 인증하지 않은 요청은 401, 허용되지 않은 계정은 403으로 거절하고 응답 캐시를 금지한다. 통계용 API는 R2 사진 저장소의 사용 가능 여부와 분리한다.

## 8. 변경 범위

- 고객 화면: `dist/index.html`, 공통 스타일·가격표 스타일, 필요한 시각 자료와 독립 통계 스크립트.
- 관리자: `dist/admin.html`, `dist/admin.js`, 관리자 스타일 및 통계 전용 모듈.
- 서버: `src/worker.mjs`의 명확히 분리된 수집·조회 경로와 통계 모듈.
- 저장소: `db/schema.ts`, 새 Drizzle 마이그레이션.
- 빌드: 현재의 정적 파일 포함 방식에 새 자산·모듈을 등록한다.
- 안내·검증: 개인정보 안내, README, 통계 테스트와 기존 회귀 테스트.

새 프레임워크로 전체 서버를 교체하거나 인증·푸시 체계를 다시 만들지 않는다. 관리자 통계의 스타일은 고객 홈페이지 개편과 충돌하지 않도록 범위를 구분한다.

## 9. 검증과 배포 기준

1. 한국 시간 자정과 시간 경계, 같은 브라우저의 반복 조회, 여러 시간 방문, 이벤트 재시도, 빈 날짜의 집계를 결정적인 테스트로 검증한다.
2. 잘못된 날짜·큰 본문·외부 출처·비정상 ID·명백한 봇, 관리자 제외, 인증·권한 실패, 보관 범위와 정리 동작을 검증한다.
3. 두 방문자와 여러 조회를 사용한 로컬 시험에서 시간별 숫자와 일 합계가 기대값과 일치하고, 저장소를 다시 열어도 기록이 유지되는지 확인한다. 운영 통계에 시험 방문을 대량 생성하지 않는다.
4. 기존 견적 중복 방지, 필수 고객 정보, 사진 업로드·권한, 접수 완료, 상담 상태, 알림 관련 테스트를 실행한다. 실제 고객 정보 삭제나 휴대폰 시험 알림 발송은 이번 검증에 포함하지 않는다.
5. 데스크톱과 모바일에서 가격표 조건, 견적 3단계, 첨부·입력 오류·제출 완료, 관리자 탭 전환과 통계 오류 상태를 확인한다.
6. 기존 네이버 소유 확인 값·canonical·구조화 정보·robots·사이트맵, 관리자 검색 제외, 접근 제어를 점검한다.
7. 새 마이그레이션을 포함해 빌드하고, 같은 Sites 프로젝트와 기존 공개 범위를 유지해 배포한다. 서버 데이터·비밀값·푸시 구독을 교체하지 않는다.
8. 배포 성공 결과와 운영 주소를 확인한 뒤 완료를 알린다. 문제가 생기면 기존 버전으로 코드 복구가 가능하도록 이전 배포를 유지하고, 추가된 통계 테이블은 견적 기능과 독립적으로 둔다.

## 10. 이번 범위에 포함하지 않는 것

유료 광고 설정 변경, 인위적인 트래픽 생성, 광고 클릭 부풀리기, 결제·온라인 주문, 기존 재고·매출 장부 변경, 방문자 신원 추적, 사이트 간 추적, 광고 플랫폼 클릭 수 연동, 별도 유료 분석 서비스 가입은 포함하지 않는다.

## 설계 자체 검토

- 승인된 가격과 별도 견적 조건을 명시했다.
- 하루와 시간별 방문자의 중복 제거 기준 및 합계 차이를 명시했다.
- 한국 시간, 수집 시작점, 저장 기간과 삭제 실행 시점을 명시했다.
- 방문 수치를 실제 사람 수나 광고 클릭 수로 오인하지 않게 했다.
- 기존 고객 데이터·관리자 권한·알림·SEO·별도 장부의 보존 범위를 명시했다.
- 외부 도구의 현재 연결 상태와 아직 생성하지 않은 결과물을 구분했다.
- 구현·배포 전 검증 조건과 오류 격리를 명시했다.
